# Save resilience — 0.8.0-beta.1
Keep existing config path and schema v1; accept legacy unsealed files and seal on next save. SHA-256 covers exact serialized UTF-8 text; not encryption or anti-cheat. Write to .tmp, flush, reopen and validate, then copy a readable prior primary to .bak.tmp, verify and replace .bak, then replace primary. Never rotate an invalid primary into the backup. Loader prefers primary, then previous-generation backup, then valid staged file only if no committed copy is readable. Recovery is shown in menu; latest actions may be lost. Preserve staged-only valid generation before next write. File-size guard 4 MiB. Fault fixtures exercise legacy, 40 rotations, valid-syntax alteration, interrupted staging, missing primary, invalid files and blocked staging path. Existing semantic board and campaign validators remain. Legacy files lack a checksum, so parseable legacy corruption may not be detected by this layer; sealed saves detect accidental content changes. No promise of hardware durability/fsync, simultaneous process coordination, or backup beyond one generation. CI and actual Windows disk/termination tests pending. Stable rollback 6a41495. No changes to background, gameplay, or audio.
