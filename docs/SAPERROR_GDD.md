# SAPERROR
## MASTER GAME DESIGN DOCUMENT · v1.0
**The numbers don't lie. Usually. / Числа не брешуть. Зазвичай.**

Статус: проєктна специфікація, не звіт про реалізацію. Платформа першого релізу: Windows x64. Мови: українська (uk), англійська (en). Жанр: сюжетний puzzle roguelite / психологічний Analog Horror. Рушій: Godot 4.x (рекомендовано; зафіксувати конкретну стабільну версію перед стартом). Авторська назва робоча; перевірити доступність назви перед публічним релізом.

**Мета:** завершена гра з початком, навчанням, кампанією, кульмінацією, фіналом і титрами. Усі цифри балансу та обсягу нижче — початкові цілі для тестування, а не вже доведені параметри. Не роздувати обсяг за рахунок основного циклу або якості.

## 01 / Бачення та межі
Гравець — оператор застарілої експериментальної станції MINE. Він відкриває клітинки, декодує дані та виявляє аномалії, які приховує система. Спочатку звичайна робота, згодом — спроба зрозуміти, чому термінал пам’ятає його попередні сеанси. Головна відмінність від звичайного «Сапера»: можливість перемикати математичні способи зчитування того самого поля, отримуючи нові докази замість випадкового вгадування.

**Стовпи дизайну:**
- Логіка перед удачею. Числа правдиві щодо активного правила; винятки явно пояснені й математично перевірювані.
- Кожен сектор — маленька загадка, кожен забіг — власний білд. Модулі не замінюють мислення, а створюють альтернативні стратегії.
- Атмосфера через взаємодію: живий термінал, шум, паузи, роздруківки, повідомлення; не за рахунок читабельності або несправедливих скримерів.
- Якість як у самостійній інді-грі: авторські ассети, узгоджений інтерфейс, анімації, аудіо, наратив і завершений фінал.

Орієнтир: 20–40 хвилин на повний стандартний забіг; кампанія приблизно 3–5 годин з навчанням і повторними спробами (перевірити на плейтестах). Повторне проходження: інші білди, кінцівки, складності та seed. Аудиторія: любителі логічних головоломок, атмосферних інді-ігор та roguelite. Референси: Minesweeper — логіка; Balatro — синергії; Inscryption — наратив через інтерфейс; Buckshot Roulette — фізичність і напруга. Не копіювати чужі ассети, персонажів чи UI.

**Поза scope v1.0:** мультиплеєр, обов’язковий онлайн, мобільні релізи, зовнішній ШІ, мікротранзакції. Архітектура має дозволяти подальші порти. Не потрібні сервер чи інтернет для основної гри.

## 02 / Сюжет, початок і фінал
Робоча історія: станція MINE колись використовувалась для відновлення пошкоджених архівів. Після інциденту №17 система ADMIN почала ізолювати «небезпечні» фрагменти пам’яті. Оператор отримує наказ очистити десять секторів і відновити доступ. Згодом з’ясовується, що дані — записи попередніх операторів, зокрема самого героя. ADMIN прагне зберегти експеримент, а невідомий голос ECHO намагається допомогти зупинити цикл. Неоднозначність мотивів розкривається через журнали та вибір, а не випадкові скримери.

**Перші 10 хвилин:** меню з вибором мови й доступності; коротке включення термінала; наказ; інструктаж; перший безпечний сектор; контрольний сектор із модулем; повідомлення ECHO, яке суперечить офіційному наказу; перший вибір маршруту. Гравець завжди розуміє, що робити далі.

**Кампанія:** 4 акти, 10 секторів у сюжетному забігу, збереження на контрольних точках між актами. Повтор невдалого забігу починається з акту, якщо це дозволяє складність; Hardcore — з початку. Сюжетні записи відкриваються один раз, повтори можна пропустити. Кінцівки доступні без нескінченного гринду.

| Акт | Сектори | Розвиток та кульмінація |
|---|---|---|
| I — BOOT | 01–03 | Навчання, класичні числа, перший картридж, WATCHER |
| II — CORRUPTION | 04–06 | Модифікації правил, зараження, архіви, LIAR |
| III — ECHO | 07–09 | Паралельні шари, повернення станів, розкриття інциденту, LOOP |
| IV — ADMIN | 10 | Фінальна багатофазна головоломка та рішення долі системи |

**Три кінцівки:** SHUTDOWN — зупинити експеримент (доступна після перемоги над ADMIN); CONTAINMENT — зберегти архів, ізолювавши ADMIN (зібрати 3 ключові записи); REWRITE — звільнити ECHO та змінити протокол (3 записи + завершити необов’язкову логічну задачу REWRITE). Перед вибором показати вимоги, без прихованих незворотних умов. Для кожної — власна сцена, текст, звук, титри, запис у галереї. Після фіналу: вільні забіги, вибір складності, класичний режим, журнал кінцівок. Зразок діалогу: ADMIN: «Ваше завдання — очистити сектор». ECHO: «Ти вже очищав його. Подивись на дату». EN: “Your task is to clear the sector.” / “You've cleared it before. Look at the date.”

## 03 / Основні правила та керування
Поле прямокутне. Закриті клітинки містять міни або безпечні дані; відкриті показують кількість мін у визначеному сусідстві. ЛКМ відкриває; ПКМ перемикає прапорець; середня кнопка або Space на відкритому числі — chord (відкрити немаркованих сусідів, якщо очікувана кількість мін та кількість прапорців і відомих нейтралізованих мін збігаються); клавіші 1–4 — інструменти; Tab — правило зчитування; Esc — пауза. Передбачити повне переназначення, клавіатурну навігацію, підтвердження ризикованого chord за налаштуванням. Прапорець — припущення, не доказ; помилкове маркування можна виправити без штрафу.

Перший хід кожного звичайного поля безпечний (у стандарті бажано нульова область 3×3, якщо дозволяють параметри). Flood fill відкриває зв’язані клітинки з нульовою кількістю мін та їх числову межу згідно з активною топологією; прапорці не чіпає. Для INVERT перед chord і flood перетворити показане число на кількість мін: |N| мінус кількість безпечних сусідів; видимий нуль у цьому режимі НЕ означає безпечну зону. Сектор завершено, коли відкрито всі безпечні клітинки або використано явно дозволений альтернативний вихід. Не вимагати правильної розмітки всіх мін для перемоги. Підрив відкриває міну як нейтралізовану, коштує одну одиницю цілісності, перериває серію; число сусідів надалі враховує цю відому міну. Нуль цілісності — завершення забігу. Після підриву показати причину, статистику, повтор або продовження з контрольної точки.

**Цикл:** вхід у сектор → читання правила → логічне відкриття/маркування → заряд і кредити → вибір евакуації чи бонусної задачі → винагорода → магазин/маршрут → наступний сектор → бос → фінал. Евакуація доступна лише після основної цілі; бонусні комірки та окремі необов’язкові задачі дають додаткову здобич, не блокують фінал. Пауза не рухає ігровий час; за замовчуванням загрози залежать від ходів, не реального часу.

**Математична чесність:** зберігати незмінну маску мін у звичайному секторі; N(c,r) — набір сусідів клітинки c для правила r; показане число дорівнює сумі мін у N. Для INVERT — кількість безпечних сусідів, включно з відкритими. Для WRAP — унікальні сусіди, координати за модулем; без самої клітинки. При зміні правила всі відкриті числа синхронно перераховуються, індикатор топології завжди видимий, історія попередніх чисел доступна. Ніколи не міняти приховано міни, щоб підлаштуватися під хід.

## 04 / Картриджі, аномалії, боси
Картридж — альтернативний спосіб зчитати те саме поле. До завершення сектору доступний CLASSIC; розблоковані альтернативи перемикаються безкоштовно для перегляду, але відкриття клітинок відбувається за активною топологією. Гравець бачить карту сусідства на hover/фокусі. Якщо правило змінює chord/flood, це показано в підказці. Немає обов’язкового платного перемикання для логічного розв’язання.

| Правило | Сусідство / зміст |
|---|---|
| CLASSIC | 8 суміжних клітинок |
| CROSS | 4 ортогональні |
| DIAGONAL | 4 діагональні |
| INVERT | Безпечні сусіди серед класичних |
| RANGE II | Радіус Чебишова 2, до 24 сусідів |
| WRAP | Класичне сусідство із замкненими краями |
| PARALLEL | Два явно позначені поля A/B, спільні підказки через видимі зв’язки |

Приклад: біля центральної клітинки 2 ортогональні та 1 діагональна міна; CLASSIC=3, CROSS=2, DIAGONAL=1, INVERT=5 для внутрішньої клітинки. Використовувати в навчанні.

| Аномалія | Правило та контргра |
|---|---|
| PHANTOM | Позначені числа тимчасово приховані; журнал і сканер відновлюють дані |
| MIMIC | Спотворює вигляд закритих клітинок, але не істинні числові підказки |
| MAGNET | Лише спеціальні пазли: видимий цикл перестановки мін, попередження та перерахунок |
| PARASITE | Через 3 дії блокує позначені безпечні клітинки; доступне очищення; не створює таємних мін |
| PORTAL | Позначена пара додає видимі зв’язки в сусідство; дублікати вилучаються |
| LOOP | Видимі контрольні стани; відкат локальної ділянки за явним правилом |
| DOUBLE | Два шари, зв’язки та підказки відображаються окремо |
| NULL | Обмежує добровільні інструменти в позначеній зоні, не блокує потрібний доказ |
| INSTABILITY | Передбачувана зміна активного правила на визначеному ході |

Не всі аномалії потрібні відразу; PHANTOM, PARASITE, PORTAL, LOOP, DOUBLE — пріоритет. MAGNET та інші складні ефекти реалізувати лише після тестування розв’язуваності; якщо не вдається гарантувати чесність, залишити у фіксованих авторських задачах або вимкнути до виправлення.

**Боси:** WATCHER — три позначені групи чисел закриваються через 5 дій, але журнал зберігає докази; LIAR — спеціальні помічені датчики дають одне спотворене значення, контрольні суми визначають правильне (звичайні числа залишаються правдивими); LOOP — два відновлювані часові стани з чіткими переходами; ADMIN — три фази (зміна сусідства, паралельний шар, фінальна логічна задача). Боси — авторські/сертифіковані задачі, не просто великі поля. Перед кожним — короткий інструктаж, візуальний сигнал фаз, повтор без повторного перегляду катсцени. Після перемоги — сюжетна нагорода.

## 05 / Економіка, модулі та комбінації
Стандарт: 3 цілісності, 30 кредитів, 2 заряди сканера на старті. За сектор: 25 кредитів, +1 за кожні 5 безпечних клітинок, бонус 10 за відсутність помилок; необов’язкові задачі +10–20. Магазин між секторами: 3 модулі/картриджі з пулу, 1 ремонт (30 кредитів за 1 HP), заряд (12), оновлення асортименту (8, зростає на 4). Ліміт 4 пасивних модулі; заміна з попередженням. Рідкість: звичайні, рідкісні, експериментальні. Дублікати не складаються, якщо явно не дозволені. Модулі не можуть створювати нескінченні цикли винагород. Усі числа — стартові для плейтесту.

| Модуль | Ефект (стартовий баланс) |
|---|---|
| Рентген / X-Ray | Кожні 10 безпечних відкриттів: +1 заряд сканера, максимум 2 за сектор |
| Друге життя / Second Life | Ігнорує перший підрив за сектор, один раз |
| Резонанс / Resonance | 3 однакові послідовні ненульові числа: +4 кредити |
| Хрономант / Chronomancer | Один безкоштовний відкат за сектор |
| Паразит прибутку / Profit Parasite | +50% секторної винагороди, −1 до максимуму HP (мінімум 1) |
| Помічник / Assistant | Один логічний доказ безпечної клітинки за сектор |
| Ланцюгова реакція / Chain Reaction | Flood з 8+ клітинок: +1 заряд (до 2/сектор) |
| Третє око / Third Eye | Один раз показує кількість мін у вибраній групі 3×3 |
| Запобіжник / Fuse | Перша шкода після 12 безпечних відкриттів блокується |
| Архіваріус / Archivist | +10 кредитів за перший необов’язковий архів у секторі |
| Екранування / Shielding | Один раз захищає від ефекту PHANTOM/NULL |
| Конденсатор / Capacitor | Максимум зарядів +2, один заряд при купівлі |
| Патч / Hotfix | Очищує одну аномальну зону за сектор |
| Стабілізатор / Stabilizer | Відтерміновує PARASITE на 2 дії |
| Аудитор / Auditor | Після 15 чистих відкриттів +6 кредитів, до 2/сектор |

Активні інструменти: сканер (доказ гарантовано безпечної клітинки; якщо такого немає, без витрати запропонувати додаткову підказку), відкат (відновлення поля, HP, кредитів, серій і RNG; заряд відкату не повертається), захисний екран (1 удар), очищення (1 позначена зона), аналізатор (додаткова достовірна числова підказка). Приклад білду: Resonance + Archivist + Capacitor → більше ресурсів → більше аналізу; Chain Reaction + X-Ray → заряд за великі відкриття з лімітами. Серія — число безпечних відкриттів без шкоди; flood зараховується один раз як дія, але відкриті клітинки окремо для модулів із лімітом. Ефекти виконуються у фіксованому порядку та логуються.

## 06 / Складність, навчання та режими
| Параметр | Story | Standard | Expert | Hardcore |
|---|---|---|---|---|
| Початкова цілісність | 5 | 3 | 2 | 1 |
| Поле (типові межі) | 6×6–10×10 | 8×8–14×14 | 10×10–18×18 | 10×10–18×18 |
| Щільність мін | 10–14% | 12–20% | 16–24% | 18–26% |
| Підказки | 3/сектор | 1/сектор | 0 безкоштовних | 0 безкоштовних |
| Аномалії одночасно | 0–1 | 1–2 | 2–3 | 2–3 |
| Контрольні точки | кожен сектор | початок акту | початок акту | лише resume, без retry |

Щільність — ціль до перевірки генератором, а не жорстка вимога. На всіх рівнях гарантувати розв’язуваність без обов’язкового вгадування, враховуючи доступні картриджі й безкоштовні інформаційні дії. Складність зростає через дедукцію, розмір поля та взаємодію правил, а не обман. Відключення CRT/скримерів не змінює механіку чи досягнення. Стандарт — рекомендований новачкам після інструктажу; Story — для сюжету.

Навчання інтегроване у світ: 1) відкрити безпечну клітинку; 2) прочитати число й підсвітити сусідство; 3) поставити/зняти прапорець; 4) дедукція через два числа; 5) chord і flood; 6) безпечна демонстрація підриву й відкату; 7) CLASSIC/CROSS/DIAGONAL на тому самому полі; 8) магазин і модулі; 9) перша аномалія. Кожен етап має авторське поле, ціль, підказку, перевірку фактичної дії, повтор і пропуск. Довідник доступний з паузи, з прикладами українською та англійською. Навчання не покладається лише на текст або колір.

Режими v1.0: Campaign (4 акти, 3 кінцівки); Free Run (після першого завершення кампанії, 10 секторів із seed, без обов’язкових діалогів); Classic (звичайний сапер, 3 розміри, без аномалій і модулів, таймер необов’язковий). Опційне розширення після v1.0: нескінченний режим, щоденний seed, таблиця результатів, персонажі з власними стартовими модулями.

## 07 / Художня біблія: Analog Horror
Візуальна ідея: не браузерна сітка із зеленим фоном, а повноцінний екран старої промислової машини. Гравець бачить фізичний термінал у напівтемній кімнаті: металевий корпус, потертості, гвинти, заводські маркування, скло, пластик, вбудовані кнопки, кабелі й світлодіоди. Основний екран займає більшу частину композиції. Глибина досягається шарами 2D/2.5D, а не обов’язковим повним 3D. Стиль дорослий, стриманий; жах через атмосферу, несправності, повідомлення та відчуття спостереження.

**Палітра (sRGB):** фон #080C0A, корпус #232A27, тінь #101714, зелений фосфор #A1D8A0, приглушений зелений #53775D, бурштин #E5B86C, небезпека #D36C60, світлий текст #D8E3D5. Не використовувати неон усюди. Для чисел 1–8 — розрізнення кольором і формою/значенням, не лише відтінками. Для чисел 9–24 у RANGE II — окремий компактний двоцифровий стиль без обрізання. Мінімум WCAG AA як ціль читабельності основного тексту; перевіряти контраст із CRT увімкненим та вимкненим.

**Типографіка:** ліцензований моноширинний шрифт із повною українською кирилицею (наприклад, IBM Plex Mono, після перевірки ліцензії) для даних; Montserrat для меню й довгого тексту. Не використовувати псевдокирилицю. Файли шрифтів, ліцензії та атрибуція — у репозиторії, якщо ліцензія дозволяє. Логотип SAPERROR — оригінальний wordmark із контрольованим розривом сигналу, читабельний у малому розмірі.

**Композиція 1920×1080:** верх — номер сектору, режим, сигнал, цілісність, кредити; центр — CRT з ігровою сіткою; праворуч — картриджі, активне сусідство, модулі, журнал; низ — фізичні кнопки, рядок повідомлень, сканер, відкат, захист. Поле завжди головний фокус; розміри від 1280×720 до 4K адаптивно; UI scale 75–150%, масштаб і панорамування поля для великих сіток, без втрати доступу до кнопок. Повноекранний, віконний і borderless режими. Не накладати на інтерактивні елементи нерозбірливе декорування.

**CRT:** скан-лінії, легка віньєтка, фосфорне світіння, шум, незначна кривизна/хроматичний зсув тільки на декоративному шарі. Усі кліки мають точно відповідати клітинкам: або трансформувати координати курсора, або залишати сітку без деформації. Глітчі контекстні, короткі, локальні. Без швидкого миготіння за замовчуванням; окремі перемикачі CRT, шуму, викривлення, скримерів, трясіння та спалахів; режим Reduced Motion. Не вимагати ефектів для розв’язання задач.

**Реальні графічні ресурси обов’язкові.** Створити авторські PNG/WebP і векторні елементи, а не фінальний UI зі стандартних кнопок Godot і однотонних прямокутників. Спочатку затвердити один повноцінний gameplay keyframe, title screen, набір клітинок і модулів; далі єдиний art bible, рев’ю кожного екрану за цим зразком. Згенеровані або намальовані ресурси імпортувати в проєкт, обрізати, перевіряти альфа-канал, масштаби, шви, права. Зображення-референс не є готовим UI: текст, цифри, кнопки, фокус і лічильники повинні бути живими та локалізованими.

## 09 / Технічний дизайн і перевірка логіки
Рекомендація: Godot 4.x, типізований GDScript, Windows x64, Compatibility renderer як базова сумісна опція; конкретну версію рушія й шаблонів експорту зафіксувати в CI. Обрати 2D сцени, Control для UI, Theme ресурси, ShaderMaterial для декоративного CRT, AnimationPlayer/Tween для візуальних ефектів, AudioBus для міксу. Не додавати непотрібні плагіни або залежності. Офлайн. Ціль продуктивності: 60 FPS при 1920×1080 на середньому ПК; перевірити також інтегровану графіку та 720p. Не обіцяти підтримку неперевірених конфігурацій.

**Архітектура:** незалежна логіка BoardState/BoardRules/Generator/Solver; RunState/RunController; Effects/ModuleSystem; Campaign/Narrative; SaveService; Settings/Locale; UI/Audio/VFX. Дані модулів, картриджів, секторів і діалогів — версіоновані ресурси з унікальними ID; контрольований порядок ефектів. Сигнали лише для повідомлень, не приховані мутації логіки. Seed та RNG стан зберігаються, візуальна випадковість має окремий RNG. Мінімізувати глобальний стан; відокремити чисту логіку від дерева сцен, щоб тестувати headless.

**Генератор і solver:** спочатку маска мін після першого ходу; seed, обмеження безпечної області, параметри сектору; далі незалежна перевірка дедуктивним solver. Початкові правила: відоме число дорівнює відомим мінам → решта безпечні; число мін дорівнює кількості невідомих → усі невідомі міни; підмножини обмежень; за потреби обмежений перебір узгоджених моделей, щоб довести безпечність або міну. Для різних картриджів враховувати обмеження кожної доступної топології. Solver не може використовувати приховану маску як джерело висновків; маска доступна лише окремому валідатору для звірки результату. Якщо дедукція зупинилась, генерація повторюється з детермінованим підseed; обмежити час/кількість спроб; fallback — перевірене авторське поле потрібної складності. Зберігати сертифікат розв’язання (послідовність доказів), не показувати його гравцю без запиту. Для рухомих аномалій тестувати переходи станів та доступність доказів; за неможливості доведення використовувати авторські сценарії.

**Save:** версія схеми, активний забіг, seed/RNG, стан поля, активне правило, маркування, інвентар, цілісність, кредити, аномалії, сюжетні прапори, чекпоїнти, налаштування, статистика; атомарний запис через тимчасовий файл з backup, валідація, міграції та зрозуміле відновлення. Локація user://, без вимоги прав адміністратора. Hardcore дозволяє вихід/продовження одного стану, але не офіційний rollback після програшу; не обіцяти античит для локальних файлів. Автозбереження після завершеної дії/сектору та при виході, без подвійної видачі винагороди при повторному запуску.

**Структура:** project.godot; scenes/{boot,menu,game,shop,boss,endings}; scripts/{core,board,solver,run,effects,save,ui}; data/{modules,rules,sectors,dialogues}; assets/{art,ui,audio,fonts,shaders}; localization/; tests/; docs/; build/; .github/workflows/; export_presets.cfg; README.md; CHANGELOG.md; LICENSES.md. Великі вихідні файли зберігати обґрунтовано (Git LFS тільки якщо справді необхідно); не комітити .godot, секрети та локальні кеші. Релізні ассети не загубити через gitignore.

## 10 / GitHub, CI/CD та EXE
Запропонований окремий приватний репозиторій: mazerfaker/SAPERROR (ім’я власника/доступ перевірити в новому діалозі, не створювати дубль, не чіпати інші проєкти). GDD та дорожня карта — у docs/. Працювати від останньої підтвердженої версії, не переписувати стабільні системи без необхідності. Для кожного етапу: прочитати код і open issues → обрати маленький завершений scope → внести зміни → тестувати → commit → CI → прочитати журнали → виправити регресії → новий запуск → артефакти → changelog. Не повідомляти про успіх, поки статус і потрібний артефакт не перевірені. Якщо немає доступу до логів/запису/збірки, чітко повідомити і надати можливий альтернативний шлях.

**CI на Windows runner:** checkout; установлення зафіксованого Godot та відповідних export templates із перевіркою джерела/хешу; headless import та перевірка помилок; автоматичні тести; Windows release export (пресет Windows Desktop, x86_64); перевірка наявності EXE/PCK/ресурсів; smoke launch з обмеженням часу і логами, якщо середовище підтримує; ZIP; upload-artifact навіть для діагностичних логів при помилці. Встановити timeout, права мінімально потрібні, кешувати безпечні залежності, не зберігати токени в репозиторії. Теги стабільних версій і GitHub Release з перевіреними артефактами. Якщо CI не підтримує графічний smoke, позначити ручний Windows-тест як окремий gate. Перед релізом обов’язково ручний запуск на Windows, повний gameplay і графічний QA; headless успіх не гарантує, що UI відображається правильно.

**Артефакти кожної стабільної версії:** SAPERROR_vX.Y.Z_Windows_x64.zip (портативний EXE, за необхідності PCK та інші файли поруч, README); SAPERROR_vX.Y.Z_Source.zip (повний проєкт); SAPERROR_vX.Y.Z_Patch.zip або diff від попереднього стабільного тегу (з переліком змін і базовим комітом); тестові логи та QA report; commit/tag, посилання на run і реальні артефакти. За можливості вбудувати PCK в EXE, якщо експорт стабільний; не обіцяти один файл, якщо потрібні супровідні ресурси. Користувач має запускати гру без встановлення Godot. Для приватного репозиторію завантаження може потребувати GitHub-авторизації. Артефакти Actions мають строк зберігання; важливі стабільні збірки зберігати в Releases. Без підпису Windows може показувати SmartScreen; пояснити, не вимикати захист глобально.
